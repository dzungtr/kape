# Use ULID time-sortable IDs with keyset pagination

## Status

accepted

## Context

Task lists are time-ordered and paginated for the dashboard, and offset-based pagination degrades over large partitioned tables. The service needed an ID scheme and pagination model that work efficiently with time-range queries.

## Decision

Use ULIDs (TEXT primary key) generated by the handler runtime as time-sortable task IDs, and paginate `List` queries with a ULID cursor for keyset pagination.

## Consequences

IDs sort chronologically and support efficient cursor pagination without offset scans, but the service depends on handlers to generate valid ULIDs and the cursor contract is tied to the ULID/`received_at` ordering.
