## 1. Why this slice now

Phase 9 (Dashboard) is the next milestone after M4 (Phase 8 — Audit + Security) reaches its gate. The other M5 issues — `#84` task detail, `#85` handler routes, `#86` auth + deploy — all assume:

Generated TS types already exist at `dashboard/app/types/generated/task-service.ts`.

## 2. Goal

Deliver `/tasks` — a live, paginated task feed served by a Bun + React Router v7 framework-mode dashboard, with:

- Server-side loader returning the first page from `task-service` (no token exposure to browser).
- Server-side **SSE resource route** at `/sse/tasks` that proxies `task-service`'s `GET /tasks/stream` to the browser, keeping the cluster-internal API hidden behind the dashboard process per spec 0009 §3 + §7.1.
- Client-side `EventSource` (via `remix-utils` `useEventSource`) that prepends/upserts incoming tasks in place.
- Infinite scroll via `IntersectionObserver` on the last visible row, loading the next page from `/tasks?cursor=…`.
- A `TaskCard` (row) component with truncated ID + click-to-copy, handler name, colour-coded status badge, relative `received_at`, and a short decision summary.
- `● Live` indicator (green when SSE open, red when reconnecting).

This slice deliberately defers the full filter bar, pause/resume, bulk-select, and row action buttons from spec 0009 §6.1 to later sub-slices — see [§9 Out of scope](#9-out-of-scope) for the explicit cut.

### Step 8 — SSE upsert (live updates)

Inside the route component, use `useEventSource("/sse/tasks", { event: "message" })` from `remix-utils/sse/react`. For each event, parse JSON → upsert into a `Map<string, Task>` keyed by `task.id`:

```ts
const [feed, setFeed] = useState(() => new Map(initial.tasks.map(t => [t.id, t])));

useEffect(() => {
  if (!event) return;
  const task = JSON.parse(event) as Task;
  setFeed(prev => {
    const next = new Map(prev);
    next.delete(task.id);
    // re-insert at the front to preserve newest-first ordering
    return new Map([[task.id, task], ...next]);
  });
}, [event]);
```

Add a 600ms `data-just-updated` flash class on the status badge for the task id that just arrived (driven by a `useEffect` that sets, then clears, the highlight set).

**Test:** mock `useEventSource` to push a fabricated task; assert `screen.findByText("01TESTID")` appears at the top.

### Step 9 — Infinite scroll

Add an empty sentinel `<div ref={endRef} />` after the last row. Inside the route component:

```ts
useEffect(() => {
  if (!endRef.current) return;
  const obs = new IntersectionObserver(entries => {
    if (entries[0].isIntersecting && nextCursor) loadMore();
  });
  obs.observe(endRef.current);
  return () => obs.disconnect();
}, [nextCursor]);
```

`loadMore()` calls `listTasks({ cursor: nextCursor, limit: 50 })` **via a client-side fetch to the same route** (`/tasks?cursor=…` returning JSON when `Accept: application/json` is set) — pattern: define `loader` to detect JSON requests and return `data({...})`; client uses `useFetcher()` to call it. Append new tasks to the `Map` (de-duped by id; SSE arrivals win over older snapshot rows).

Test: mock `IntersectionObserver` and `useFetcher` (`@react-router/dev` ships test helpers, or wrap the route render in a `createMemoryRouter` setup). Assert the loader is hit a second time with the cursor from the first page.

## 8. Edge cases and risks

| # | Edge case / risk | Mitigation |
|---|---|---|
| 1 | **SSE proxy back-pressure** — Bun's `fetch` returns a `ReadableStream` body; passing it directly into a `Response` should preserve back-pressure, but if it doesn't, slow consumers cause memory bloat in the dashboard pod. | Step 4 test runs a 2-frame upstream; add a follow-up perf check in a deploy ticket. If we see growth, switch to a `TransformStream` that respects controller.desiredSize. |
| 2 | **Idle proxy disconnects** — OAuth2 Proxy and most Ingress controllers idle-close HTTP/1.1 streams after 60s. The current `task-service` SSE handler emits no heartbeat. | Resource route writes a `: ping\n\n` comment every 15s into the response (a TransformStream tee). Tracked as **explicit acceptance**: comment frames are ignored by `EventSource`. Add a Vitest case asserting heartbeat emission. |
| 3 | **SSE message > one task per frame** — current handler writes one task per `data:` line, with a trailing `\n\n`. If a future change ever splits a task across frames, our naive `JSON.parse(event)` breaks. | Document the wire contract in `sse.tasks.ts` JSDoc + add a Vitest case where the upstream emits a multi-line `data:` to confirm we still parse correctly (the browser concatenates them per the SSE spec). |
| 4 | **Cursor stability across SSE arrivals** — between the initial load and a `loadMore()` call, SSE may have inserted N tasks; if cursors are `received_at`-based, the next page should still be consistent (cursor is opaque, anchored to the snapshot of the last row). | Confirm in Step 9 by inspecting `task-service`'s cursor encoding (`task-service/internal/infrastructure/postgres/task_repository.go` `Cursor` handling). If it's ULID-based and stable, no issue. If it's offset-based, file a follow-up to switch — but the OpenAPI doc already promises `next_cursor`, so we trust the contract here. |

## 12. Open questions for the implementer

These are not blockers — sensible defaults are listed — but flag them in the PR description if a different choice is made:

- **`react-router-serve` vs hand-rolled server entry?** Default: use `react-router-serve` (one-liner CMD, no custom server code). Re-evaluate only if we need request middleware (e.g. injecting `X-Forwarded-User` from OAuth2 Proxy — but that lands with #86, not here).
- **Tailwind v3 vs v4?** Default: v3 (stable). v4 alpha API churn is not worth the friction for a small UI.
- **Single `tasks/_index.tsx` vs `tasks._index.tsx` filename?** React Router v7 supports both via the routes table — `tasks/_index.tsx` (folder layout) reads better when sibling routes land. Use it.
- **Cursor encoding** — opaque string per OpenAPI. Don't introspect it; just pass it through. Confirm with the implementer of `task-service`'s `ListTasks` (current state already returns `next_cursor: string | null`).
